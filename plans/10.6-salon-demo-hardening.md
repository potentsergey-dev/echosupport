# План доводки салонного демо Booking

**Статус на 3 августа 2026:** в `main` уже находятся базовые исправления
групповой записи (коммиты `9967a28`–`ef489df`). Локальная ветка синхронизирована
с GitHub `main` на `ef489df`.

## Что уже работает

- Услуги фильтруются по возможностям специалиста.
- Групповой слот учитывает записи `PENDING` и `CONFIRMED`, а также число людей
  из `Group participants: N`; свободное место возвращается как `remainingSeats`.
- Backend проверяет вместимость при создании и изменении групповой записи.
- Повторная запись того же клиента на групповой слот обновляет одну запись, а
  админка показывает услугу и число участников.
- Tool contract запрещает создавать запись без услуги и отделяет индивидуальные
  услуги от групповых.

## Незакрытые риски

1. `find_available_slots` требует специалиста. Поиск по услуге и дате без
   специалиста невозможен: агент вынужден угадывать или уточнять лишнее.
2. Контракт и промпт не задают достаточно строгий сброс контекста при смене
   услуги; старый специалист или групповые правила могут попасть в новый запрос.
3. Тесты покрывают backend-расчёты, но не все реальные диалоги и не гарантируют
   компактную, непротиворечивую формулировку агента.
4. Не проведена проверка с реальными демо-данными и LLM после объединения всех
   предыдущих изменений.

## Рабочий порядок

### Шаг 1 — зафиксировать диагностику и регрессионные тесты

- Добавить тесты: 5 из 6 мест занято; запрос на 4 места при остатке 1; успешная
  запись на 4 участников; индивидуальная услуга без `group_participants`.
- Проверить, что «грязная» запись без `serviceId` блокирует группу только как
  пересекающееся занятие, а не ошибочно учитывается как место нужной услуги.
- Сохранить тестовые транскрипты восьми пользовательских сценариев из контекста
  задачи как acceptance-тесты prompt/tool contract.

**Готово, когда:** unit-тесты воспроизводят каждый дефект без обращения к LLM.

### Шаг 2 — поиск по услуге без специалиста

- Расширить `find_available_slots`: принимать `service_id` или `service_name`
  без обязательного специалиста.
- На сервере находить всех активных специалистов данного агента, которым доступна
  услуга, вызывать расчёт для каждого и возвращать структурированные группы
  `{ specialist, service, slots }`.
- Не менять поведение точного поиска с указанным специалистом; при несовместимой
  паре возвращать понятный результат, а не выбирать другого молча.
- Ограничить выдачу на одну дату/диалог 5–8 ближайшими слотами с сохранением
  `remainingSeats` для групп.

**Готово, когда:** «Dimensional color во вторник» возвращает свободное время всех
подходящих специалистов, без привязки к ранее выбранной Еве.

### Шаг 3 — контекст и UX агента

- Обновить описание tools и системный prompt: вопрос об услуге без даты → коротко
  подтвердить и спросить дату, без поиска слотов и длинного описания.
- Явно считать новую названную услугу сменой контекста: сбрасывать несовместимого
  специалиста, выбранный слот и правила групповой записи.
- Закрепить формулировки: слот считается недоступным только по ответу backend;
  при выборе даты сначала сообщать о проверке; при отсутствии слотов предлагать
  другой день.
- Для группы требовать число участников только после выбора слота; для
  индивидуальной услуги никогда его не запрашивать.

**Готово, когда:** тестовые диалоги не содержат противоречий, выдуманной
недоступности и избыточных списков.

### Шаг 4 — интеграционная проверка и выпуск

- Прогнать `pnpm typecheck`, `pnpm test`, lint и сборку.
- Пройти вручную все десять сценариев на демо-агенте с реальными данными и
  проверить создание/редактирование в админке.
- Открыть отдельную ветку и PR, дождаться зелёного CI, затем merge в `main`.
- После merge подготовить точные команды обновления VM, не выполняя деплой без
  отдельного подтверждения.

**Готово, когда:** CI зелёный, сценарии пройдены, а production-обновление имеет
проверяемый rollback-путь.

## Приоритет следующей реализации

Начинаем со **шага 1 + шага 2** в одном небольшом PR: они закрывают основной
функциональный пробел и дают надёжную опору для последующей настройки prompt.
